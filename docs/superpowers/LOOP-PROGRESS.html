Now — draining the 88, and the harness that has to be trusted first

2026-08-12 · 33 of 88 closed

The visual oracle photographed a frozen world, and the clock built to fix that was still run-dependent. Determinism was bought by SUPPRESSION — 218 isCaptureMode() sites across 65 files — so nothing that only manifests in motion could regress. The frame clock shipped 08-09 under a commit titled "step-then-shoot"; capture.mjs, 766 lines and 31 screenshot sites, never called it. And the clock itself advanced once per RENDERED frame, so the captured phase was whatever the machine drew: same box, same schedule, two runs read [6,10,13,15,16] and [6,11,13,14,16]. It is a COMMANDED clock now, and every run reports 31/31 frames pinned at 90 (1.50s virtual).

The sun casts shadows in the gated frames — the one conversion of 41 that the 6% threshold can resolve. A 17-agent survey proposed 41; the value pass refuted all but this. Its calibration is the argument: the entire QUESTS panel is 7.51% of a frame, the whole spell-cast VFX ensemble 0.64%. Every baseline had depicted a world with no sun shadows for the oracle's entire life. Determinism was measured rather than assumed — two runs with shadows on, worst self-diff 0.185% against 0.210% before them.

Then the density instrument reached a verdict, and immediately found something. It had computed a windowed local density on every frame for three days under the words "REPORT ONLY, asserts nothing". Armed as a per-frame ratchet, it fired on its first run: explore-day concentrated 30.35% of a 128px window while the global gate passed at 1.625%. Cropping both frames showed a distant treeline present in one run and thinner in the other — the chunk-streaming defect diagnosed BY HAND twice before (S8 1.646%, S9 0.201%). Root cause: waitForStableFrame counted WALL TIME on a renderer managing 1-3 fps, so two polls 200ms apart routinely landed inside the same rendered frame and "identical" meant nothing was drawn. Frame-gated now: byte-identical frames went 18/31 to 23/31, and explore-day-low went 4.49% to 0.38%.

And a beacon that had never been visible to anyone. The sky-arch's <Emissive> was a 2.0 cube at the IDENTICAL centre as a span with half-extents (6.1, 1.2, 1.1) — fully enclosed, writing no fragment, so <Bloom> had nothing to bloom. The S8d commit that made it "brighter + bigger" in answer to a faint-beacon report was tuning an object sealed inside a rock. Raised; confirmed on screen by cropping the new baseline at the window the ratchet named.

The 88-finding queue: 33 closed, 55 open. A 16-agent triage read every one against live HEAD, each partition asserting its own denominator. 12 were already fixed (stamped with the commit that actually closed them, found by git log -S, not by stamping HEAD) and 8 were dismissed with a runnable proof — including one whose premise I checked myself rather than on report: navigator.deviceMemory is not clamped to 8, it reads 32 in the Chrome this ships against, so the tier the finding called dead is reachable. Of the rest, the adversarial pass refuted the proposed GATE on 31 of 64 — nearly always a mutation that touched the defect's line without reproducing its shape.

Latest — closing the full-source audit, one mutation-proven commit at a time

2026-08-11 · 97 of 108 · every HIGH closed

The Building Tools panel did nothing, and had done nothing since it shipped. Reachable four ways — KeyB, the HUD grid button, the touch tray, the panel registry — localized into two languages, writing buildingMode / buildSize / selectedBuildBlock into the store, and nothing read them. Every mode placed exactly one block: an advertised pillar of a voxel building game, inert. Wired now, but not as specced, and the reason is the economy rather than the code — place debits per block, so the panel's size-10 cube is 1000 blocks in one click and 1000 worker messages. The footprint is cell-capped at 64 and each mode's usable size is DERIVED from that cap, so no mode can define its way around it. No E2E had ever placed a block in this repo; one does now, and it took five iterations, every failure being the test rather than the wiring.

The ELEMANCER imbue loop was one cast out of phase for its entire life. The latch decided consume inside useFrame, one frame after the projectile had already spawned and already read the element slot — so the cast that PAID got imbueKind: null, and the kind sat parked for the NEXT cast to take for free. The advertised prime cast key, F, never stamped the latch's input at all, so on that path the stance idled armed forever. Two findings, one mechanism: the consume moved into the call that spawns the projectile. Its unit test was green throughout — it tested the slot in isolation, arm then consume, which is exactly the green-gate-over-a-seam-that-never-runs pattern this repo documents.

The trauma model was not the model that ran. trauma.js documents Eiserloh's screenshake — a 0..1 value, added per event, decayed per frame, magnitude scaling as trauma² — and both functions implementing it had zero callers, with a green test file the whole time. What shipped: absolute writes of 1.4–1.8 that were then SQUARED (1.78 world units of camera offset), REPLACING rather than accumulating so a light tick cut a heavy shake short, and a bare ×0.85 per FRAME so shake lasted 0.52s at 60Hz and 0.26s at 120Hz. Producers speak in impact weight, not trauma, so the weight is now MAPPED into range rather than clamped at the door — clamping would flatten 1.6 and 1.8 onto the same value and destroy the hierarchy the curve exists to express — and the conversion is exactly feel-preserving for a single hit.

Geometry, measured in pixels. The touch spell ring fanned items around a FULL circle from a control pinned to the bottom-right edge, so item 1 landed at right: -52px: a 52px button beginning exactly at the viewport's right edge, zero tappable pixels, iceball permanently unreachable. A quarter arc does not fix it — four 52px targets need ~122px of separation at r=78, which is what a full circle gives and no 90° arc can. The corner does not have 360° of room, so the ring was the wrong SHAPE for its anchor. It is a fan row now. The old gate asserted the glyph was in the jsdom document; jsdom has no layout, so it could not have caught this under any circumstances.

Also closed: invisible corpses stopped eating the shot aimed past them (targeting.js was the one module in the game that did not filter health <= 0, and it is the one projectile hit-resolution goes through); a burning mob stopped shaking the player's camera four times a second after the cast; a Shift pressed on the title screen stopped coming back as an unrequested roll; rain and fireflies stopped wearing the last snowflake's rotation; and the clock stopped keeping two origins a quarter cycle apart.

Six source-grep gates went RED at the FIX rather than at a defect — pinning a parameter name, a character window around a call, an inline block's exact text. Every one was re-anchored to the behaviour it existed to protect, and mutation-proven afterwards; none was relaxed. That is its own finding about how this repo writes gates.

The second half of the drain found things the audit had not. The autosave trigger gate derived its expectation from saveSchema's progression block ALONE, so the whole of game_state — including bossState, rewritten on every damage tick — sat outside its denominator: a melee-only boss fight with a few quiet seconds before the tab closed lost the entire encounter, while a spell-using one survived only because casting happens to touch an unrelated field. A gate reporting clean over the half it never examined is the defect it exists to catch, one level up.

Two more mutations stayed green, and both times the mutation was wrong rather than the code. A CJK-font latch reproduced with an early flag but a corrected tail is not the defect — the defect is latching and never correcting. A quest-lore gate that walked a hardcoded id list could not see a renamed key; its denominator now comes from the map itself. And a defeat-sting assertion read |frequency|, so a sweep that crossed zero and turned around still looked like a descent from any single late window.

gate-shape blocked three attempts to add a source-grep gate — for the hot-path allocations, for the exit tweens, for the HUD contract — and it was right each time. The A* neighbour table and the debris park became pure modules, the exit tween became a rendered assertion about deferred unmount, and the HUD scan moved to tests/_support. In one of those the grep ALSO false-positived on a panel that declares no exit variant at all, which is its own argument.

16 agents · 7 dimensions · adversarially verified

Verdict: mechanically excellent, epistemically unreliable. Seven dimensions re-derived the loop's claims against live HEAD; every finding was then handed to an adversarial verifier told to refute it. 36 CONFIRMED · 25 PARTIAL · 2 REFUTED.

The five rules

every scar, encoded
01 · MUTATION-PROVE

Break the behaviour → it must go RED → revert via cp-backup, never git checkout. A gate never seen red is a rubber stamp.

02 · VERIFY THEN ASSERT

Every external/absence/root-cause claim gets a live check the same turn. The registry is a hypothesis.

03 · GREEN ≠ LIVED

A green headless gate isn't a lived result. Audio / render / feel → a lived probe or Kevin. Pure logic → a pure unit.

04 · NEVER WEAKEN TO PASS

A gate green on day one against unfixed code proves nothing. Assume vacuous until seen red.

05 · NOT SELF-JUDGED

The worker may not certify its own completion. Findings are adversarially verified before they count.
