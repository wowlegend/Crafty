# Upside pass (upside-generator-kz, 2026-10-27)

Decision: Choose the bold move, the compositions and the door calls that make Crafty unforgettable rather than merely polished. The constraints are no money, cool on an M3 Max and correct on iPad Safari. Path keys: src/ = frontend/src/, wt/ = wt/frontend/src/, sp/ = docs/superpowers/.

Win: **"Reclaim the Light."** Make light the game's single system of progress and its look at the same time. The fiction Crafty already wrote supplies it: the Hearth, the Ember Frontier and the Blight Heart. Old Pike's quest line already says "Light the frontier shrine. Each one we reclaim weakens the Blight Heart", and nothing implements it [FACT src/game/questLore.js:24].
1. **Night gets a key light.** Today night is mood 1, which is the dusk palette held all night [FACT src/render/mood.js:99-102, src/theme/tokens.js:22-27]. The sun is written with no horizon gate [FACT src/render/Atmosphere.jsx:295-296], and the moon is a fixed painted disc [FACT src/render/skyDome.js:65-73]. I opened explore-night.png: it shows an orange, sun-lit "night" with an elliptical moon. The move drives the colour script by sun elevation, and below the horizon the moon takes over the existing directional light.
2. **A baked voxel light field.** Sky light plus block light, baked per vertex, carried in the greedy-merge key and shaded through a lookup texture keyed to time of day and mood. None of it exists today [FACT: a grep for `blockLight|skyLight|lightLevel|lightField` over src finds 0; it is queued as R2 #5, sp/sota-2026-09/EXTERNAL-BASELINE-R2.md:124-141]. The first sources are lanterns and the Hearth's forge and lookout glows [FACT src/render/HubRender.jsx:29].
3. **Light is the verb.**
   - No hostile spawns in light 8 or above.
   - Siege waves march on your brightest structure.
   - "Light the shrine" becomes a hold-the-light event. Success makes the shrine a permanent light source and turns its beam from cyan to ember gold, which costs almost nothing because FarBeacon already draws a cyan shrine beam and a violet Blight beam [FACT src/world/Terrain.jsx:552-607].
   - Each lit shrine is saved (a `shrinesLit` count) and strips HP and one trick from the dragon, up to 3 shrines. That makes Pike's line true.
4. **The screenshot.** From the Hearth at blue hour: a moonlit world, warm lantern pools, and a road of gold beams you lit, running out to the violet Blight pillar. Every player shares the same world [FACT: WORLD_SEED 12345, src/world/terrain.worker.js:38].

What it buys if it works:
- In one system: the looks lane's #1 transformative finding, the gameplay lane's shrine, siege and encounter findings, and R2 #5, each paying the others.
- A signature that iPad's low tier also shows. It lives in baked vertex data, palette constants and a light every tier already has, not in N8AO or GodRays, which low lacks [FACT src/render/quality.js:20].
- Almost no added GPU cost [INFERENCE: one lookup-texture fetch, no new lights].
- [BET] That light-as-defence is fun in Crafty. Same variable: R2:37-41 measured what peer games shipped, not whether Crafty's players enjoy it. Cheapest test: a lantern plus the spawn rule behind a flag, three nights played by a player-lens reviewer.
- Widen the reach. iPad becomes a first-class rail (the touch hold fix lands first). Add a share rail [BET]: photo mode plus a "postcard" link carrying seed, world version, camera pose and time into the same deterministic world. Today the only URL parsing is the perf probe [FACT src/devtest/perfProbe.js:17-26].

- Fix locally vs upgrade three and its post-processing library: sequence them.

Door:
- **(a) Lantern block id 16 is one-way for players' saves.** world_data stores raw block ids [FACT src/game/saveSchema.js:18], and ids 0-15 are taken [FACT src/world/blockIds.js:28-49]. Once a pushed build lets a player save a lantern, a rollback cannot render it, and removing it needs a migration (the version seam exists, src/game/saveSchema.js:10). It closes at the first push that ships it. Texture, light level and recipe stay free to change.
- **(b) Reversible:** the light field is derived and never saved. `shrinesLit` and the ember cache are added save fields that default to 0.
- **(c) three 0.172→0.186 plus @react-three/postprocessing 3.2.2:** reversible on a branch. What actually closes is tuning S1 and S2 by eye on a renderer you then leave. r174 already moved 19 of 31 frames over the gate and saturated the sky [FACT sp/DECISIONS.md:144-146]. Decide before S1 tuning starts, after a branch A/B of the sky saturation. If undecided, keep every look constant as data.
- **(d) Baselines:** never bundle the renderer rebaseline, the engine bump and the look pass in one rewrite, or no change can be attributed.
- **(e) WebGPU:** stay out until R3F v10 is stable and two Safari 27.x point releases ship without a WebGPU regression.
- **(f) Postcard links:** links in the wild freeze their URL schema, so put seed and world version in v1.
- **(g) Every push is public** [FACT memory/ACTIVE_PLAN.md:72-73]. Loaders must tolerate unknown save fields.
- **(h) Recorded audio:** a shipped file has been redistributed, so CC0 only (Kenney). The Sonniss bundle is not a candidate until its licence is read.

Rails:
- **Tiers.** Bloom is mounted at every tier [FACT src/GameScene.jsx:119-124], so the HDR signals read on low. The claim that low keeps the signature is INFERENCE until the lookbook compares low and high at night.
- **Input.** Holds on keyboard and mouse. On touch it holds only after the hold fix. Shrine lighting needs a contextual on-screen hold prompt, driven by G on keyboard and by touch, as its rail-neutral form.
- **Browsers.**
  - The light field, the lookup texture and the moon key need only WebGL2, which both engines have.
  - GPU timer queries exist only in Chromium, so Safari's governor signal stays the frame rate.
  - Every new ramp must be delta-based, because Safari runs at 60 Hz and iOS Low Power Mode at 30 (research lane, not re-checked).
- **Capture oracle.** The signature is deterministic, so the oracle can guard it. But capture pins the sun at noon [FACT src/render/Atmosphere.jsx:130], so add capture states declared at about 0.62 and 0.75: make explore-night true rather than deleting it.
- **Locale and deploy.** en and zh-CN through i18n. Static Vercel hosting, no paid service.

Script, written with `cat > <session-scratchpad> <<'PROBE_END'`:
   ```
   import { isLandmarkChunk } from 'frontend/src/world/landmarks.js';
   const R = Number(process.argv[2] || 16);
   const near = [];
   for (let cz = -R; cz <= R; cz++) {
     for (let cx = -R; cx <= R; cx++) {
       if (!isLandmarkChunk(cx, cz)) continue;
       const d = Math.hypot(cx * 16 + 8, cz * 16 + 8);
       if (d <= R * 16) near.push(Math.round(d));
     }
   }
   near.sort((a, b) => a - b);
   let corridor = 0;
   for (let cz = -2; cz <= 50; cz++) {
     for (let cx = -2; cx <= 50; cx++) {
       if (!isLandmarkChunk(cx, cz)) continue;
       const x = cx * 16 + 8, z = cz * 16 + 8;
       const along = (x + z) / Math.SQRT2;
       const off = Math.abs(x - z) / Math.SQRT2;
       if (along >= 0 && along <= 1024 && off <= 96) corridor++;
     }
   }
   console.log(JSON.stringify({ radiusChunks: R, withinRadius: near.length, nearestMeters: near.slice(0, 8), blightCorridorWithin96m: corridor }));
   PROBE_END
   ```
