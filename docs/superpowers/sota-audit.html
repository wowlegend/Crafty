The visual-test harness is not failing at the thing we were fixing

A SOTA audit of the capture, comparison and baseline layers. The capture layer is above industry standard. The comparator is behind. The oracle — the committed baselines themselves — is ungoverned, and had never been audited by anyone.

00 Status — every recommendation is now disposed of

BOTH DEFERRED ITEMS ARE NOW SHIPPED, and the comparator was the one that mattered. This audit's headline was that the comparator is behind and the oracle ungoverned. The oracle got its trailer gate on 2026-08-09. The comparator's per-frame tolerance was deferred as "a red gate nobody can act on" — correct, and an objection to a SINGLE threshold rather than to asserting at all. It shipped 2026-08-12 as a PER-FRAME RATCHET: each frame frozen at what it actually does, only a rise fails, no adjudication and no invented tolerance.

It found a real defect on its first armed run. explore-day concentrated 30.35% of a 128px window while the global 6% gate passed it at 1.625%. Cropping both frames showed a distant treeline present in one run and thinner in the other — the chunk-streaming variance diagnosed BY HAND twice before (S8 at 1.646%, S9 at 0.201%) and never closed. Root cause: waitForStableFrame measured WALL TIME on a renderer managing 1-3 fps, so two polls 200ms apart routinely landed inside the same rendered frame and "two identical screenshots" meant nothing had been drawn. Frame-gated now: byte-identical frames went 18/31 to 23/31, explore-day-low 4.49% to 0.38%.

And the suppression finding is being reversed, carefully. The audit's other structural point — the gated frames depict a build nobody plays — now has a commanded clock behind it (31/31 frames pinned at 90, a declared 1.50s virtual) and its first conversion: the sun casts shadows in the gated frames. A 17-agent survey proposed 41 conversions and the value pass refuted all but that one, on measured grounds — the entire QUESTS panel is 7.51% of a frame, the whole spell-cast VFX ensemble 0.64%. The cap on this programme was never the clock; it was the oracle's resolution, which is what the ratchet above raises.

Updated 2026-08-12 — the two deferred items have landed, and one of them found a defect on its first run

Per-frame tolerances still want n≥10 separate-process captures. failOnFlakyTests still wants 10 consecutive clean CI runs; a per-shard flaky reporter now accumulates that record in the run log, so the count is a thing anyone can read rather than something a future session has to remember to grep.

The liveness gap this page identified has an instrument now. V8 coverage collected while Playwright drives a real booted session answers the one question coverage-zero's own header admits it never could — did the GAME reach this module, not did a test. First run: 262 of 282 src modules executed. Building it caught the instrument lying about itself: page.coverage cannot see Web Workers, so ten modules including the greedy mesher were about to be reported as code the game never reaches.

And the suppression finding — "the gated frames depict a build nobody plays" — is being worked, not just recorded. The missing half of capture determinism was a deterministic CLOCK: seeded RNG shipped long ago, nothing ever substituted time, which is why 116 guards turn systems off instead of substituting. That clock now exists, ticks once per animation frame across all three Canvases, and can be driven to a declared frame index before a shot. Probing it in a real browser rewrote the plan: two seconds of wall time under capture advanced the world by two frames, so a clock alone gives determinism without motion, and step-then-shoot is required rather than optional.

2026-08-11 — what fixing 53 of those 108 said about the gates themselves

Six source-grep gates went RED at the FIX rather than at a defect. One asserted the juice dial appeared within 400 characters before a call — it failed because a COMMENT was added above that call, so it was reporting on formatting. One pinned a parameter's NAME, and went red when the argument was correctly renamed from intensity to weight. One pinned the exact inline text of a block that had to move out of a throttle. Every one was re-anchored to the behaviour it existed to protect and mutation-proven afterwards; none was relaxed. That is a finding about how this repo writes gates, and it is the same shape as this audit's central one: an instrument that reports on the wrong thing looks healthy right up until you need it.

Two of the fixes were caught by a green mutation, not by review. A recipe gate written to forbid a recipe named after something it does not produce sailed straight through the historical Bow → Arrow case, because its rule asked whether the recipe NAME was a registered item — 'Bow' is not, and 'Arrow' is perfectly real, so both halves looked fine. A green mutation IS the finding; the rule became a stem match between title and output, which every legitimate divergence satisfies and Bow → Arrow does not. The other: a HUD contract check whose key list had drifted into being exactly the selector's own keys, so it could only confirm that the selector agreed with itself. Deriving that list from the CALL SITES found a live TypeError on its first run — a setter called unconditionally on the chest-close path and never selected, four lines below the comment describing the identical defect.

The suppression finding advanced. The first E2E in this repo's history to place a block now exists, and the first to assert an ordering INSIDE a single page.evaluate — because the ELEMANCER latch bug reached the same end state one frame late, so any assertion taken after a frame boundary reads identically in the broken and fixed builds. That is the liveness gap this page named, closed one verb at a time rather than by a coverage number.

2026-08-12 — the audit never asked whether the PROBES could run, and fifteen of them could not run together

Six ports, fifteen probes. 4196 was claimed by four separate probes (heldf, ocean, soulbind-eyes, magic-panel), 4195 by three, and 4194 / 4198 / 5197 / 5199 by two each. Every probe binds with --strictPort, so a collision does not fall back to a free socket — the second process dies on bind, and the failure presents as a broken probe rather than as two probes wanting one port. It compounds with the orphaned-vite bug this harness already fixed: a leaked server from a crashed run squats the shared port and reddens a different probe, for reasons in nobody's diff. This repo has already spent a session on exactly that confusion, on the capture port.

This page audited capture, comparison and the oracle — and treated the probe fleet as plumbing. That was the gap. The probes are the only instruments here that observe the game in motion, which is precisely the coverage hole the audit's central finding is about; an instrument that cannot be started is a coverage hole that never files a report. Allocation now lives in _serve.mjs as a frozen table behind probePort(import.meta.url), so a new probe that forgets to register gets an error naming its own file instead of a silent collision — the same move that ended the process-leak class, put in the shared instrument rather than in a convention.

Gated in both directions and mutation-proven four ways: no two entries share a port, the table and the directory agree BOTH ways (one direction alone lets an unregistered probe ship or lets the table rot reserving ports for deleted files), probePort refuses an unregistered name, and no probe re-hardcodes a literal. Each assertion was broken individually and went RED on its own test. Verified as a lived result too, not just a green suite — hud-probe ran to completion on its new port with 0 processes leaked afterward.

And ocean-coast's density failure was diagnosed by the harness's own instrumentation, which nobody had connected to it. capture.mjs emits WARN: frame never stabilized after 34 polls (8.5s) -> THIS FRAME IS NOT DETERMINISTIC and re-baselining it would freeze noise — on exactly THREE frames, in BOTH independent runs: ocean-coast, landmark, explore-day-med. So the 2.20% (then 3.70%) local-density failure is inherent instability, not a regression. True run-to-run variance on identical code AND identical renderer: 22/30 byte-identical, explore-day 30.35% local / 1.536% global, ocean-coast 3.70%.

Which makes the density ledger's real defect precise. 29 of its 31 entries are the DENSITY_FLOOR constant rather than measurements, so for most frames the ratchet compares against an arbitrary number — that is what ocean-coast failed against. The fix is to freeze from this A/B pair, NOT to raise the floor, and NOT to re-baseline the three unstable frames' images (the capture says in as many words that doing so freezes noise). Freezing a frame's DENSITY at its measured variance and re-baselining its PIXELS are different acts; only the first is safe here.

② Is antialiasing granted under the software rasteriser?

Yes — 4× MSAA, and the request is honoured in both directions (antialias:true → granted:true, SAMPLES 4; false → SAMPLES 0). Probed with the capture's exact launch flags. And it explains a signature: exactly one surface asks for AA — TitleDiorama, which is the menu frame — while GameScene sets antialias:false. So the single MSAA frame was the single noisiest frame, and its diff showed “hairline outlines tracing every edge”, which is what an MSAA resolve does to a small geometric difference. AA was the amplifier, not the cause: MSAA is deterministic given identical geometry, and the residual reached 0.0000% with no AA change at all. Anyone reading “AA was on” as the diagnosis would blur the frame and remove no variance. It also confirms includeAA:false — the antialiasing-aware default, whose name reads backwards — is the correct setting here, now measured rather than assumed.

01 Verdict

Every defect this harness has actually shipped was a coverage or content failure. Not one was a tolerance failure.

Four beast-* baselines that were pictures of an empty mountain. Seven of 31 frames captured, baselined, and absent from the STATES array for weeks — 23% of the gate's apparent coverage was decorative. Grass motes rendered at the world origin. Mob grass-bending that never ran.

03 Two recorded conclusions that were wrong

Killed — the recorded next step

--deterministic-mode and --font-render-hinting=none are absent from the Chrome binary Puppeteer actually launches. Verified by running strings on the installed Chrome for Testing 147.0.7727.57 — both exist only in chrome-headless-shell, whose single consumer is headless/lib/browser/command_line_handler.cc, and which left the Chrome binary at M132.

They were step 1 of the plan written into ACTIVE_PLAN.md and DECISIONS.md. That step would have measured nothing and reported "no effect" for the wrong reason. It must be deleted from both documents with the evidence attached.

Killed — the "confirmed 2.7× fix"

The device-pixel-ratio pin was recorded as a confirmed fix worth 2.7×. calculateDpr([1,2]) in the installed R3F 9.5.0 is Math.min(Math.max(dpr[0], window.devicePixelRatio), dpr[1]). The capture sets viewport 1280×800 with no deviceScaleFactor, and Puppeteer defaults it to 1. So [1,2] and 1 both resolve to 1 — the pin was arithmetically inert for this frame, and the behavioural gate written to guard it gates a no-op.

The 0.984 → 0.359 improvement sits inside the metric's own spread: 0.359–0.557 was measured with the fix in place. Two lanes disagreed here; the arithmetic favours "inert". Do not cite 2.7× as a magnitude anchor.

05 The menu frame

The problem is cross-process state, not renderer nondeterminism and not a settle-condition failure. Three shots from one page are byte-identical; separate processes differ by 0.36–0.98%. Every proposal that attacked frame scheduling was attacking the wrong axis — which is exactly why frameloop='always' could not have helped, and did not.

Cropping the diff shows two signatures: hairline outlines tracing every edge of the mascot, and background motes appearing as pairs of bars — the left edge from one frame, the right from the other. The channel-delta histogram is bimodal: 18,092 deltas of exactly 1 (subpixel), with a tail reaching 240 (something moved).

Resolved — and this section's diagnosis was right

Both signatures are now explained and both are gone. The tail-reaching-240 half was the animated phase: capture guards that early-returned left the mascot's hat-tip, gem pulse and the mote ring wherever the run happened to have got to, and boot length varies 1.68–10.43 s per process. The delta-of-1 half was 4× MSAA on this frame alone resolving those small geometric differences into hairline edges — the amplifier, not the source. Resetting to declared values took the frame to 0.0000% with no AA change whatsoever.

Precondition — one cheap line, do it first

Log whether the diorama canvas exists at the moment capture mode is switched on. The component is React.lazy, and the harness waits for that canvas after the flip. If it mounts after, the hero never animated, and both the proposed fix and the already-landed camera fix are inert. That single reading retroactively validates or refutes the camera commit. (Checked: the canvas is present. Neither is inert.)

Did anything found here make it actually reproducible?

No. Honest inventory of what was killed: BeginFrameControl — the one true render-exactly-N-frames primitive — is a target-creation parameter Puppeteer never sends, and macOS is hard-refused in target_handler.cc. The determinism flags are absent from the binary. frameloop='never' + advance() is inert, because the capture guards skip rather than substitute — 58 suppression guards against 11 substitutions — so nothing in that canvas reads the clock under capture and stepping 120 frames yields the same scene graph as stepping one.

Tolerance is the terminus, and it is legitimate. Sequence: verify mount order, land the phase reset, measure with n≥5 paired captures, then set an honest per-frame tolerance with a comment naming the measurement it came from.

Update — the sequence was followed and the terminus moved. Mount order verified, phase reset landed, and the measurement came back at exact equality, so there is no residual left for a tolerance to accommodate on this frame. Tolerances are still owed for the others, still on n≥10.

06 Refuted — so they are not re-proposed

  • pixelmatch windowSize — the highest-value-looking lead in the whole audit. The main-branch README documents it with a rationale that reads as if written for this project. It does not exist in any published version. Adopting it would have produced a silently non-functional gate.
  • includeAA: true — the name reads backwards. The default false is the antialiasing-aware setting. (Since confirmed to matter: this frame really does carry 4× MSAA, so the default is not merely safe here, it is load-bearing.)
  • Perceptual hashing — engineered to be invariant to brightness and contrast shifts, which is a lighting regression. Useless as a pre-filter too, since 13–20 frames are already byte-identical and a buffer compare is free.
  • SSIM as a blanket replacement — ~3× slower, and it tolerates signal as well as noise. Epic's renderer suite: "they may hide the existence of real errors just because a human couldn't see them."
  • LLM/VLM-as-judge — disqualified on non-reproducibility, not accuracy. Legitimate only as post-red triage.
  • Tolerant settle-condition — the proposed tolerance sits above the 0.189% signature of the late-chunk regression the function exists to catch. It would blind the guard to its founding defect.
  • Threshold auto-calibration (tier = 4× measured self-diff) — self-relaxing. Run against a noisy day's data it mints >100% tolerances: permanently unfailable gates, committed and printed as "calibrated".
  • Stryker mutation testing as scoped — aborts in the dry run three ways; 113 of 131 gate tests read source as text, which instrumentation destroys.
  • Scene-graph invariant sweep and draw-call budget as specified — both blind to the defects they were sold on. Mote placement lives in an instance matrix that traverse never visits; the post-frame counter read returns the last fullscreen pass, green on day one.
  • New browser engines. 17 candidates evaluated, 16 ruled out. Cloudflare's Kitesurf cannot render WebGL at all and explicitly trades away pixel fidelity. Firefox hard-disables WebGL in headless in source. Servo and Ladybird publish no determinism claim in either direction.

07 Declined on purpose

  • Hosted visual-review SaaS. All derive signal from run volume and multi-reviewer workflows; several scope themselves to teams of 20+. Plus cloud upload of unreleased game art. But keep the idea — Argos's product thesis is recommendation 3, and rejecting the vendor threw out the governance concept with it.
  • Migrating capture to Playwright. The orchestration has almost nothing to do with the browser driver, and every piece of it encodes a specific past failure. Playwright also pins its own Chromium per version, making baseline churn worse. Take the ideas; leave the migration.
  • Moving the visual gate to CI. All baselines are macOS arm64; runners are Ubuntu x86-64. Cross-platform WebGL pixel parity is a published research problem. Worth doing cheaply: a Linux self-consistency job that captures twice and diffs run A against run B, touching no baseline. (Since decided explicitly: declined — see §00. The signal is covered twice over by the in-process determinism gate and the 0.0000% cross-process result.)
  • Visual gate in pre-push. Measured 733 s, including 37 s of literal sleeps. The fix is making the gate trustworthy, not mandatory.
  • Coverage threshold gates. A coverage gate rewards execution, while the existing gate-shape gate exists to reject assertions satisfied without verification. (Since: a zero-coverage REPORT landed — which modules no test executes at all — with no threshold, deliberately.)

08 Assumptions the audit broke

  1. "RNG is seeded." The per-key seeded generator exists and is sound — and has exactly one consumer file. 73 raw Math.random() sites remain across 18 files. Determinism is achieved by suppression, not seeding.
  2. Consequence nobody had stated: the gated frames depict a build with weather, mob AI, NPC routines, particles, spawning and VFX turned off. The gate validates a version of the game nobody plays, and is structurally incapable of regressing anything that only manifests in motion.
  3. "Clocks are frozen." No global freeze — seven scattered per-consumer substitutions against 68 time-reading sites and 52 timers. Nobody enumerated which run under capture.
  4. Three of the 31 gated frames cannot exist in the shipped bundle. They are dev-only components behind a DEV guard, and the capture runs against the dev server. So ~10% of the gate tests surfaces that never ship, and 0% tests the artifact that auto-deploys on every push. Raised by zero research lanes.
  5. The baseline sentinel is written but read nowhere — the comparator hardcodes the current directory.

All five were acted on: 1 and 3 are corrected in the project's own instructions (which had claimed the opposite), 4 produced a production-bundle smoke job, and 5 is wired — the comparator now attributes each frame to the capture that produced it.
