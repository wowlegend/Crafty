## The outcome in five lines

- **Open work falls from 441 rows to 265, plus 15 lane rows.** 193 open rows close, each with its proof checked. 326
  rows that were already closed get a typed resolution and a kind. There are 32 new rows: 12 lane rows, and 20 that

## Schema v2

The full design is in `docs/superpowers/specs/2026-10-31-registry-v2-design.md`. These are the fields, with the decision each lets someone make:

| Field | Decision it supports |
|---|---|
| `id` | Cite a row forever. It is never renamed or reused. |
| `key`, `planUnit` | Provenance, kept until plan row 32 retires the old sources. |
| `title` (160 characters at most) | Act from a list view without opening the note. |
| `kind` (bug, feature, debt, instrument, flake, decision, process, lane) | Route the row, and know what evidence closes it. |
| `area` (13 parts of the game and repo) | Which rule file applies, and whether a runtime-seam reviewer is needed. |
| `severity` (HIGH, MED, LOW; `unrated` only in triage) | Fix order inside a lane. |
| `playerVisible` | Tell game defects from harness rows. |
| `owner` (command session, Kevin, AB Command) | Who can close it. Your rows never close on inference. |
| `state` (open, in-flight, closed; closed is final) | Is someone on it? Is it over? |
| `lane` | Who owns it now, and the orphan check. |
| `acceptance` (one checkable line) | When it is done, and what proof to cite. |
| `blockedBy`, `reopens` | What can start now, and which fixes did not hold. |
| `evidence` (path:line @sha) | Re-resolve it at HEAD before trusting it. |
| `note` (1,500 characters at most) | Dated facts, merged duplicate facts, and the won't-fix reason or false-positive proof. |
| `opened`, `updated` | Age and staleness. |
| `resolution`, `closedBy` | How it ended, with typed proof: shas, `DECISIONS <date> item N`, `duplicate:<id>`, `superseded:<ids>` or `PR #N`. |

**Changes to the rubric found in synthesis.** The verifiers found these conflicts. Each fix is recorded here and in the
DECISIONS entry:

1. **R4 binds only rows that were v2 at the base.** A row is v2 once it carries `kind`. The rubric froze a closed row's
   title, but also capped every title at 160 characters, and 113 closed titles were longer. Under this fix the one-time
   migration may retitle and rate the old closed rows. After it, a closed row's title and severity are frozen.
2. **`done` accepts `PR #N`** when the row's whole task was to close that PR. This covers QUEUE:Q01, Q05 and
   OPEN_ITEMS:OI-04, OI-05.
3. **A won't-fix, false-positive or obsolete reason is a sentence anywhere in the note**, starting "Won't fix:",
   "False positive:" or "Obsolete:". It does not have to open the note. Before, appending a reason to a row that
   already had a note could never pass.
4. **Lane rows carry no `lane`.** A lane row's severity is the highest of its open rows.
5. **One placeholder, `@TRIAGE@`, for the one DECISIONS item this cleanup writes.** It stands in 57 closures (49
   won't-fix, 4 false-positive, 3 done, 1 superseded). The reviewers had spelled it several ways. The migration refuses to
   run until it is given the real item.

## The gates that keep it clean

No new gate script. The tree rules go into `registry-harvest.mjs`, run in every unit run. The range rules go into
`registry-append-only.mjs`, run on pre-push and in CI.

| Rule | Fails when |
|---|---|
| S0 | A field outside the v2 set. |
| S1 | A bad line, or an id that repeats. |
| S2 | A required field is missing or outside its enum. |
| S3 | An open row lacks a lane, area or acceptance (20 to 240 characters, not the title), or carries a closure. |
| S4 | **The orphan check:** an open row's lane is missing, not a lane, or closed. |
| S5 | A closure's `closedBy` does not fit its resolution, or its reason or proof sentence is missing. |
| S6 | A sha in `closedBy` is not an ancestor of HEAD. |
| S7 | A DECISIONS reference does not resolve to exactly one item. |
| S8 | A pointer dangles, a duplicate chains, or a row points at itself. |
| S9 | A bug that no player can see; a decision closed without a DECISIONS item; a Kevin row closed outside his rules. |
| S10 | `unrated` outside triage, or a triage row older than 7 days by HEAD's commit date (so main never turns red on its own). |
| S11 | A title over 160 characters or a note over 1,500. |
| R1 | A row is deleted (exists today). |
| R2 | A closed row reopens. |
| R3 | A row's text changes without its `updated` date moving. |
| R4 | A row closed at the base, already v2, changes anything but its closure fields, note, kind, area, lane or acceptance. |

## How it stays a masterpiece

1. **Intake.** These rules go in `.claude/rules/registry.md`, path-scoped to the registry:
   - Write a row only for work you will not do in this change.
   - One row per root cause; a new sighting is a note on the existing row.
   - Search open rows by area before writing one.
   - Fill kind, severity, lane and acceptance when the row is written.
2. **Triage has a clock.** `LANE:triage` is for bulk intake only, such as an audit or a review round. A row left there 7
   days fails the next push. So triage is a two-minute job at each landing, never a pile.
3. **A lane cannot land and leave orphans.** Closing a lane row fails S4 while any open row names it. This is the rule
   that would have stopped the 230-row rot.
4. **Closed is final.** A regression is a new row with `reopens`. This keeps the union merge and `registry-dedupe`
   correct.
5. **Views are generated, never committed.**
   - `npm run orient` prints one line: open rows by kind and severity, waiting on Kevin, triage overdue, orphans.
   - `orient -- --registry lane|kind|area|owner` lists the open rows grouped, with HIGH first.
   - The Command Record builds its "waiting on you" and "fix lanes" sections from the registry, instead of copying them
     by hand.
6. **The backlog is watched, not purged.** orient lists any backlog row 60 days stale. Closing on age is closing on an
   assumption, so nothing auto-closes.
7. **Then plan row 32.** Once the migration lands, the old sources can be retired: STATUS section 2, QUEUE, OPEN-ITEMS
   and the masterpiece tables. Then `registry-harvest`'s extraction half and `registry-floors.json` can be deleted.

## Win, Compose, Door, Rails, Threat

- **Win.** Lanes as rows plus the orphan gate turn "who owns this?" from a judgment into a failing check. The Command
  Record's lanes and "waiting on you" sections stop being hand-kept.
- **Compose.**
  - The migration and plan row 32 run in sequence: the cleanup makes row 32 cheap, and row 32 retires a gate.
  - Schema and data land in one PR, so the gate is shown red on the old data first.
- **Door.**
  - "Closed is final" is the one one-way door.
  - The field set, the enums and the closedBy grammar can each be widened later by a DECISIONS entry.
  - Ids and their prefixes stay frozen; new prefixes are free.
- **Rails.** It holds on every channel that reads the registry: unit runs, pre-push, CI with full history, `orient`,
  the Command Record and the cold-takeover eval. The union merge stays.
- **Threat.**
  - **A sha that fixed something else.** S6 proves ancestry, not relevance. The verifier's `git show --stat` is the
    check, and future reviews keep it.
  - **The file grows.** It is about 870 KB after the migration. When it passes about 2 MB, closed rows older than 90 days
    can move to `memory/registry-archive.jsonl`, with both gates reading the two files as one id space. That is
    deferred, and it gets its own row when it is near.
